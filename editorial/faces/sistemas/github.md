## Objetivo

O GitHub reúne hospedagem de repositórios, revisão por pull requests, histórico e automações. Para este site, é o local de publicação dos arquivos estáticos.

## Pontos que precisam ser desenvolvidos e revisados

1. **Pergunta de partida:** transformar a ideia principal em uma pergunta clara e delimitada.
2. **Fundamentação:** aprofundar o seguinte eixo, distinguindo princípios, resultados e hipóteses: Git registra alterações em commits e permite recuperar estados anteriores sem reescrever o histórico. Branches isolam experimentos; testes automatizados reduzem o risco de publicar uma alteração que afete outros módulos.
3. **Exemplo ou demonstração:** detalhar uma aplicação reproduzível: Um fluxo mínimo: criar branch de teste, modificar um módulo, executar vistoria, revisar diff e publicar com um commit de escopo limitado.
4. **Limites e desenvolvimento futuro:** Acrescentar exemplos de tags de backup, revisão de dependências e política de arquivos públicos versus privados.
5. **Materiais desejáveis:** incluir diagrama ou captura real, legenda, descrição alternativa, fonte dos dados e versão pertinente.
6. **Rastreabilidade:** acrescentar links primários verificados, data de atualização e eventuais conflitos entre fontes.

## Critérios de aceite

- O artigo contém conteúdo próprio, sem texto provisório ou afirmação biográfica não verificada.
- O link de leitura abre pelo portfólio convencional e pela face do dodecaedro.
